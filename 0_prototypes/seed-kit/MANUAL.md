# Seed Kit 매뉴얼

**코드로 만드는 스톱모션 필름**을 위한 작은 프레임워크입니다.
빌드 도구도, 라이브러리도, 이미지·사운드 파일도 없습니다. 브라우저의 Canvas 2D와 WebAudio만으로 그림과 소리를 모두 코드로 만듭니다.

이 문서는 세 부분으로 되어 있습니다.

1. **이해하기** — 프레임워크가 어떤 생각으로 만들어졌고, 한 프레임이 어떻게 그려지는지
2. **만들기** — 샷을 추가하고 움직임·소리·카메라·인터랙션을 붙이는 레시피
3. **참고** — API 목록, 자주 하는 실수, 확장 사례(`bounce-ball`)

---

## 0. 5분 시작

```sh
cd seed-kit
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000
```

> ES 모듈을 쓰기 때문에 `index.html`을 더블클릭(`file://`)하면 열리지 않습니다. 반드시 로컬 서버로 여세요.

| 공 클릭 | 공을 톡 차기 |

# 1부 · 이해하기

## 1.1 네 가지 약속

Seed Kit의 모든 코드는 아래 네 가지 약속 위에 서 있습니다. 이것만 지키면 무엇을 만들어도 스크럽·되감기·루프·캡처가 저절로 동작합니다.

**① 필름은 고정 규격이다.**
1920×1080, 60fps, 정해진 길이(`DUR`). 모든 것은 "몇 번째 프레임인가"로 결정됩니다.

**② 같은 프레임은 언제나 같은 그림이다. (결정론)**
어떤 프레임 `f`를 요청하면 엔진은 샷을 처음 상태로 되돌린 뒤, 고정된 1/60초 간격으로 `f`까지 다시 걸어갑니다. 그래서 앞으로 가든 뒤로 가든, 빨리 가든 천천히 가든 결과는 같습니다.
→ **`Math.random()`을 쓰지 마세요.** 대신 `rng(seed)`나 `hash(a, b)`를 씁니다.

**③ 물리는 60Hz로, 카메라는 12Hz로 본다. (스톱모션)**
시뮬레이션은 매 프레임 진행되지만, 화면에 그리는 "포즈"는 5프레임마다 한 번만 찍습니다(`snap`). 그래서 움직임이 초당 12장의 사진처럼 뚝뚝 끊어집니다. 반면 카메라는 매 프레임 부드럽게 움직입니다. 실제 스톱모션 촬영의 모션 컨트롤 카메라처럼요.

**④ 손맛은 노출 번호에서 나온다.**
사람이 인형을 매번 손으로 다시 놓으면 조금씩 떨립니다. 이 떨림(`boil`), 화면 밝기 깜빡임, 필름 그레인은 모두 **노출 번호 `e`**에서 계산됩니다. 같은 노출이면 같은 떨림이라, 이것도 결정론적입니다.

## 1.3 한 프레임의 일생

재생 중에 브라우저가 한 번 화면을 갱신할 때 일어나는 일입니다.

```
requestAnimationFrame
  └─ tick(now)                             film.js
       ├─ 시계 진행: clock += dt (DUR를 넘으면 0으로 루프)
       ├─ f = floor(clock × 60)
       ├─ simTo(f)                         ← 결정론의 심장
       │    ├─ (다른 샷이거나 뒤로 갔다면) shot.reset()
       │    └─ f에 닿을 때까지 반복:
       │         shot.step(1/60, st, sf)   물리 한 걸음
       │         5프레임마다 shot.snap()   포즈 촬영
       ├─ render()
       │    ├─ cam = shot.cam(st)          카메라는 매 프레임
       │    ├─ shot.draw(ctx, sq, e, cam)  스냅된 포즈만 그림
       │    └─ post(ctx, e)                깜빡임 · 그레인 · 비네트
       └─ fireScore(prev, clock)           지나간 악보 이벤트 연주
```

스크럽하거나 `←` `→`를 누를 때는 `seek(f)`가 불리고, 같은 `simTo → render` 흐름을 탑니다. 이때는 **물리 소리가 나지 않습니다**(`audio.live = false`). 되감기 중에 "톡톡톡" 소리가 쏟아지지 않게 하려는 것입니다.

## 1.4 네 개의 시간 변수

샷 코드를 읽을 때 가장 헷갈리는 부분입니다. 표를 옆에 두세요.

| 이름 | 뜻 | 어디서 쓰나 | 성질 |
|---|---|---|---|
| `st` | 샷 안의 연속 시각(초) | `step`, `cam` | 매 프레임 1/60씩 증가 |
| `sf` | 샷 안의 프레임 번호 | `step` | 정수 |
| `sq` | **포즈 시각**: 5프레임 단위로 내림한 `st` | `draw` | 1/12초마다 계단처럼 뜀 |
| `e` | **노출 번호**: 필름 전체 기준 `floor(f / 5)` | `draw`, `boil` | 떨림·그레인의 씨앗 |

- `draw` 안에서 시간으로 무언가를 움직일 때는 **반드시 `sq`를 쓰세요.** 그래야 스톱모션처럼 끊깁니다.
- 부드럽게 모드(`S`)에서는 `sq = st`, `e = 0`이 되어 떨림 없이 60fps로 흐릅니다.

## 1.5 샷 계약

샷은 아래 속성을 가진 평범한 객체입니다. 클래스도 상속도 없습니다.

```js
export default {
  name: 'hello',        // 이름 (디버그용)
  t0: 0,                // 필름 안에서 이 샷이 시작하는 초

  build() {},           // 한 번만: 스프라이트·배경을 캔버스에 미리 굽는다
  reset() {},           // 샷의 0프레임 상태로. 결정론의 출발점
  step(dt, st, sf) {},  // 물리 한 걸음 (dt는 항상 1/60)
  snap() {},            // 지금 상태를 "카메라가 볼 포즈"로 복사
  draw(ctx, sq, e, cam) {}, // 스냅된 포즈만 그린다
  cam(st) { return { x: 960, y: 540, z: 1 }; }, // 카메라

  score() { return []; },   // (선택) 악보 이벤트 [{ t, k, ... }] — t는 샷 기준 초
  poke(x, y) { return false; }, // (선택) 관객이 월드 좌표 (x, y)를 눌렀을 때. 맞으면 true
};
```

**`step`과 `draw`를 나누는 이유.**
`step`은 "세상이 실제로 어떻게 움직이는가", `draw`는 "카메라가 마지막으로 찍은 사진"입니다. 둘을 이어주는 것이 `snap`입니다.

```js
reset() { this.b = { x: 180, y: 260, vx: 420, vy: 0 }; this.snap(); }  // reset 끝에 snap 한 번
step(dt) { const b = this.b; b.vy += 3000 * dt; b.x += b.vx * dt; b.y += b.vy * dt; }
snap()   { const b = this.b; b.rx = b.x; b.ry = b.y; }                    // r = rendered
draw(ctx, sq, e) { put(ctx, this.ball, this.b.rx, this.b.ry); }            // rx, ry만 읽는다
```

> `draw`에서 `b.x`(실제 위치)를 읽으면 공만 60fps로 미끄러지고 나머지는 12fps로 끊기는 어색한 화면이 됩니다. **`draw`는 `r` 값만 읽으세요.**

**물리가 필요 없으면 `step`/`snap`은 비워 두세요.** 대부분의 움직임은 `sq`의 순수 함수로 충분합니다(2.3절). 물리는 튕기기, 쌓기, 굴러가기처럼 "결과를 미리 계산하기 어려운" 움직임에만 씁니다.

## 1.6 좌표와 카메라

- **월드 좌표**: 카메라가 `{ x: 960, y: 540, z: 1 }`일 때 월드 1px = 화면 1px입니다. 예제의 바닥은 `y = 900`입니다.
- `cam(st)`는 `{ x, y, z }`를 돌려줍니다. `x, y`는 화면 중앙에 올 월드 지점, `z`는 줌(1보다 크면 확대)입니다.
- **패럴랙스**: `setCam(ctx, cam, p)`의 `p`는 층의 깊이입니다.
  - `p = 1`: 인형이 움직이는 평면
  - `p < 1`: 더 먼 층이라 카메라를 덜 따라 움직입니다(예제의 벽은 `.85`)
  - `p > 1`: 카메라 앞 전경
- 배경은 카메라가 움직이는 여유만큼 화면보다 크게 구워야 가장자리가 비지 않습니다(예제: `W + 160`, `H + 90`).

# 2부 · 만들기

## 2.1 두 번째 샷 추가하기

**① 필름을 늘립니다.** `engine/config.js`

```js
export const FPS = 60, DUR = 7;    // 4초 → 7초
```

**② 샷 파일을 만듭니다.** `shots/02-star.js`

```js
// 샷 02 · Star — 노란 종이 원반이 왼쪽에서 미끄러져 들어와 한 바퀴 돈다
import { W, H } from '../engine/config.js';
import { lerp, inv, eio, boil } from '../lib/math.js';
import { sprite, put, blobPath, backdrop, setCam } from '../lib/draw.js';

export default {
  name: 'star', t0: 4,                       // 필름 4초부터

  build() {
    this.wall = backdrop(W + 160, H + 90, { top: '#7a5a6a', bottom: '#4a3444', seed: 21, mottle: .35 });
    this.star = sprite(160, 160, 80, 80, g => {
      blobPath(g, 80, 80, 80, 80, { seed: 8, amp: .06 }); g.fillStyle = '#d8a54a'; g.fill();
    });
  },
  reset() {}, step() {}, snap() {},          // 물리 없음 — 움직임은 sq의 함수

  draw(ctx, sq, e, cam) {
    setCam(ctx, cam, .85); ctx.drawImage(this.wall, -80, -45);
    setCam(ctx, cam, 1);
    const k = eio(inv(.2, 1.6, sq));         // 0.2초~1.6초 동안 0→1
    const [bx, by, br] = boil(50, e);        // 노출마다 손 떨림
    put(ctx, this.star, lerp(-120, W / 2, k) + bx, 540 + by, { rot: k * Math.PI * 2 + br });
  },

  cam() { return { x: W / 2, y: H / 2, z: 1 }; },

  score() { return [{ t: .2, k: 'whoosh', dur: 1.4 }, { t: 1.6, k: 'chime', n: 'G6' }]; },
};
```

**③ 등록합니다.** `main.js`

```js
import star from './shots/02-star.js';
SHOTS.push(hello, star);                     // t0 순서대로
```

**④ 표시 문구를 맞춥니다.** `index.html`의 시작 오버레이에 적힌 `4 s`를 바꿉니다. 재생 바의 길이와 시간 표시는 `DUR`를 따라 자동으로 바뀝니다.

**알아둘 점**
- 샷의 길이는 **다음 샷의 `t0`까지**입니다. 마지막 샷은 `DUR`까지 갑니다.
- 샷 사이는 컷 편집(하드 컷)입니다. 전환 효과가 필요하면 한 샷의 끝과 다음 샷의 처음에서 각자 그립니다(2.8절).
- `st`, `sf`, `sq`, 악보의 `t`는 모두 **샷 기준**입니다. 샷을 통째로 옮기려면 `t0`만 바꾸면 됩니다.
- 샷마다 `reset`이 따로 불리므로 샷끼리 상태를 공유하지 마세요.

## 2.2 종이 인형(스프라이트) 만들기

```js
this.ball = sprite(w, h, ax, ay, g => { /* g에 그린다 */ }, { shadow: { dx: 6, dy: 9, blur: 10, a: .3 } });
```

- `sprite`는 그림을 **한 번만** 캔버스에 굽고, 부드러운 접촉 그림자도 같이 구워 둡니다. 매 프레임 복잡한 경로를 다시 그리지 않아 빠릅니다.
- `(ax, ay)`는 **앵커**, 즉 `put`으로 놓을 때 기준이 되는 점입니다. 공이면 중심(`r, r`), 서 있는 인형이면 발바닥(`w/2, h`)이 편합니다.
- 그림자가 필요 없으면 `{ shadow: null }`을 넘깁니다.

```js
put(ctx, this.ball, x, y, { rot, sx, sy, alpha, shadow });
```

- 순서는 **이동 → 크기(sx, sy) → 회전**입니다. 그래서 찌그러짐(`sx`, `sy`)은 월드 축 기준이고, 회전은 인형 자체의 회전입니다.
- 그림자는 월드 기준으로 오프셋되므로 인형이 돌아도 조명은 한 방향입니다.

**손으로 오린 느낌**은 `blobPath`로 냅니다. 둘레를 노이즈로 살짝 흔든 타원입니다.

```js
blobPath(g, cx, cy, rx, ry, { seed: 3, amp: .035 });   // amp가 클수록 삐뚤빼뚤
g.fillStyle = '#cf4b40'; g.fill();
```

**배경판**은 `backdrop`으로 굽습니다. 그라디언트 위에 인쇄 얼룩과 먼지를 얹습니다.

```js
backdrop(w, h, { top: '#4f8b92', bottom: '#2f6369', seed: 5, mottle: .35, dust: 1400 });
```

`mottle`은 얼룩 세기입니다(0이면 매끈). 벽처럼 넓은 면은 `.3`~`.4`가 차분합니다.

## 2.3 움직임: 키프레임 방식 (권장)

물리 없이 **`sq`의 함수**로 위치를 계산하면 가장 간단하고, 스크럽에도 강합니다.

```js
const k = eio(inv(t0, t1, sq));    // t0~t1 구간에서 0→1, 부드럽게 가속·감속
const x = lerp(xFrom, xTo, k);
```

| 함수 | 쓰임 |
|---|---|
| `inv(a, b, x)` | x가 a→b 사이 어디쯤인지 0~1로 (구간 밖이면 고정) |
| `lerp(a, b, t)` | a와 b 사이를 t 비율로 |
| `eo(t)` | 빠르게 출발해 천천히 멈춤 (ease-out) |
| `eio(t)` | 천천히 출발, 빠르게, 천천히 멈춤 (ease-in-out) |
| `smooth(a, b, x)` | `inv` + smoothstep을 한 번에 |

**여러 구간을 이어 붙이기**

```js
const y = 700 - 300 * eo(inv(.5, .9, sq)) + 300 * eio(inv(1.4, 1.8, sq)); // 올라갔다가 내려온다
```

**반복 움직임**: `Math.sin(sq * 속도)`처럼 `sq`를 넣으면 끊기는 흔들림이 됩니다.

## 2.4 움직임: 물리 방식

튕기고 굴러가는 움직임은 `step`에서 적분합니다. 예제 `01-hello.js`의 공이 표본입니다.

- **상태는 `reset`에서 전부 새로 만드세요.** `build`에서 만든 상태를 이어 쓰면 되감기 후 결과가 달라집니다.
- **`dt`는 항상 1/60입니다.** 가변 dt를 가정하지 않아도 됩니다.
- **빠른 물체**는 한 `step` 안에서 몇 번 나누어(서브스텝) 적분하면 벽을 뚫지 않습니다.
- **애니메이션식 과장**: 예제는 공이 바닥에 닿으면 찌그러진 채 `hold = .06`초 머문 뒤 튀어 오릅니다. 12포즈/초 카메라가 접촉 순간을 놓치지 않게 하는 요령입니다. 물리적으로 정확한 것보다 **사진 한 장 한 장이 읽히는 것**이 중요합니다.
- **찌그러짐(squash)**은 부피를 보존하게 `sx = 1/√s`, `sy = s`로 줍니다. 앵커를 바닥 접촉점에 두면 바닥에서부터 찌그러집니다.

## 2.5 손맛: boil · 깜빡임 · 그레인

```js
const [dx, dy, dr] = boil(id, e, amt);   // 노출 e마다 바뀌는 작은 떨림
put(ctx, sp, x + dx, y + dy, { rot: rot + dr });
```

- `id`는 **인형마다 다르게** 주세요. 같은 `id`면 두 인형이 똑같이 떨립니다. 예제에서는 공이 `1`, 글자들이 `100 + i`입니다.
- `amt`는 세기입니다(기본 1 ≈ ±1.5px, ±0.01rad). 큰 글자는 `.8`, 배경 소품은 `.3`~`.5`가 적당합니다.
- 배경판은 떨리지 않게 두는 편이 좋습니다. 실제로도 배경은 고정되어 있으니까요.
- 화면 깜빡임·그레인·비네트는 `engine/post.js`가 필름 전체에 자동으로 입힙니다. 세기를 바꾸려면 그 파일의 숫자를 조절하세요.

## 2.6 글자를 한 컷에 한 자씩

예제의 "Hello, world"는 노출마다 한 글자씩 놓입니다. 핵심은 한 줄입니다.

```js
const shown = Math.floor((sq - T_TEXT) / (1 / 12) + 1e-6) + 1;   // T_TEXT부터 보이는 글자 수
```

그리고 글자마다 `boil(100 + i, e)`로 떨림을 주고, 방금 놓인 글자만 살짝 크게(`1.08`) 그립니다. `01-hello.js`의 `draw` 아래쪽을 복사해 쓰면 됩니다. 여러 샷에서 쓸 거라면 `lib/draw.js`에 함수로 빼 두세요. `bounce-ball/lib/draw.js`의 `stampText`가 그렇게 뺀 예입니다.

> 글자에 그림자를 주고 나면 `ctx.shadowColor = 'transparent'`로 되돌리거나 `ctx.save()`/`ctx.restore()`로 감싸세요. 캔버스 상태가 다음에 그리는 것에 새어 나갑니다.

## 2.7 카메라 움직이기

`cam(st)`는 **`st`(연속 시각)**를 받으므로 부드럽게 움직입니다.

```js
cam(st) {
  const k = eo(st / 4);                                    // 4초에 걸쳐 천천히 다가감
  return { x: W / 2 + k * 60, y: H / 2 - k * 20, z: 1 + k * .06 };
}
```

- **줌 아웃**(`z < 1`)을 하면 화면에 월드가 더 많이 보이니, 배경을 그만큼 더 크게 구워야 합니다.
- **핸드헬드 느낌**: `x + Math.sin(st * .5) * 8`처럼 느린 사인을 더합니다.
- 카메라를 스톱모션처럼 끊고 싶다면 `cam` 안에서 `st`를 `Math.floor(st * 12) / 12`로 바꿔 쓰세요.

## 2.8 소리

소리도 전부 코드로 합성합니다. 소리는 세 갈래로 들어옵니다.

| 경로 | 언제 울리나 | 용도 | 예 |
|---|---|---|---|
| **악보** `score()` | 필름 시계가 그 시각을 지날 때 | 연출된 소리 | 글자가 놓이는 소리, 종 |
| **emit** | 실제 재생 중에만 (스크럽 중엔 침묵) | 물리에서 생긴 소리 | 공이 바닥에 닿는 소리 |
| **sfx** | 언제든 즉시 | 관객의 손에서 난 소리 | 클릭 |

```js
// 악보: 데이터일 뿐이다. t는 샷 기준 초
score() { return [{ t: 1.25, k: 'tick', v: .35, f: 3000, pan: -.4 }, { t: 2.3, k: 'chime', n: 'E6' }]; }

// 물리 소리: step 안에서
emit({ k: 'tok', v: .6, pan: b.x / W * 2 - 1 });

// 클릭 소리: poke 안에서
sfx({ k: 'tok', v: .7 });
```

**기본 악기**

| `k` | 소리 | 주요 인자 |
|---|---|---|
| `tok` | 종이 공이 닿는 소리 | `v` 세기 |
| `tick` | 짧은 종이 소리 | `v`, `f` 음색(Hz) |
| `chime` | 작은 종 | `n` 음이름(`'C6'`, `'F#5'`), `v` |
| `whoosh` | 바람 | `dur` 길이, `f0`→`f1` 필터 이동, `v` |

모든 소리는 `pan`(-1 왼쪽 ~ 1 오른쪽)을 받습니다. 인형의 x 위치로 `pan`을 주면 소리가 화면 속 위치에서 납니다.

**새 악기 추가**: `engine/sound.js`의 `VOICES`에 함수 하나를 더합니다.

```js
pluck(ac, out, e, t) {                           // 튕기는 현
  const o = ac.createOscillator(), g = ac.createGain(); o.type = 'triangle';
  o.frequency.value = freq(e.n ?? 'A4');
  g.gain.setValueAtTime(e.v ?? .3, t); g.gain.exponentialRampToValueAtTime(.001, t + .6);
  o.connect(g).connect(out); o.start(t); o.stop(t + .65);
},
```

이제 `{ t: 1, k: 'pluck', n: 'D5' }`처럼 씁니다. 여러 악기를 겹쳐 새 소리를 만들 수도 있습니다(`tok`이 안에서 `tick`을 부르는 것처럼).

> 브라우저 정책상 오디오는 사용자의 첫 클릭에서 열립니다. 시작 오버레이가 그 역할을 합니다.

## 2.9 관객의 손: poke

```js
poke(x, y) {                                     // (x, y)는 이미 월드 좌표
  const b = this.b;
  if (Math.hypot(x - b.x, y - (b.y - BR)) > BR * 1.4) return false;  // 빗나감 → 엔진이 바람 소리
  b.vy = -1500; b.vx += (b.x - x) * 10 + 120;    // 누른 쪽의 반대로 튕김
  sfx({ k: 'tok', v: .7 });
  return true;
}
```

- 화면 좌표를 월드 좌표로 바꾸는 일(카메라 역변환)은 `engine/ui.js`가 해 줍니다.
- 판정 반경은 보이는 크기보다 넉넉하게(×1.4) 잡으면 누르기 편합니다.
- 필름이 멈춰 있을 때 누르면 재생이 시작됩니다.

> ⚠️ **poke는 결정론 밖에 있습니다.** 누른 결과는 지금 이 순간의 상태만 바꿀 뿐, 기록되지 않습니다. 그래서 스크럽하거나 루프가 돌아 `reset`이 불리면 사라집니다. 관람용 필름에서는 "만져 볼 수 있는 장난감"으로 충분합니다. 하지만 **관객의 입력이 결과를 결정해야 한다면**(게임) 입력을 기록해야 합니다. 3.3절을 보세요.

## 2.10 캡처와 테스트

모든 프레임이 결정론적이므로 헤드리스 브라우저로 원하는 프레임을 그대로 찍을 수 있습니다.

```sh
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
  --window-size=1920,1080 --hide-scrollbars --virtual-time-budget=4000 \
  --screenshot=frame120.png "http://localhost:8000/?frame=120&ui=0"
```

페이지에는 테스트 훅이 열려 있습니다.

```js
window.__film.seek(200);   // 200프레임으로 이동하고 그린다
window.__film.info();      // { f, shot, smooth }
window.__film.score();     // 합쳐진 악보 전체
window.__READY;            // 부트가 끝나면 true
```

**결정론 셀프 체크**: `seek(200)`으로 화면을 찍고, `seek(37)`로 갔다가 다시 `seek(200)`으로 찍어 두 이미지가 같은지 비교하세요. 다르다면 어딘가에서 `Math.random`, 실제 시간(`Date.now`, `performance.now`), 또는 `reset`이 초기화하지 않은 상태를 쓰고 있는 것입니다.

# 3부 · 참고

## 3.1 API 요약

**`engine/config.js`**

| 상수 | 값 | 뜻 |
|---|---|---|
| `W`, `H` | 1920, 1080 | 캔버스 해상도 |
| `FPS` | 60 | 물리·시계 주기 |
| `DUR` | 4 | 필름 길이(초) |
| `NF` | `FPS × DUR` | 총 프레임 수 |
| `EXPO` | 5 | 한 포즈가 유지되는 프레임 수 (12포즈/초) |

`EXPO`를 바꾸면 필름 전체의 스톱모션 감각이 바뀝니다. `2`(30포즈/초)는 매끈하고, `10`(6포즈/초)은 거칩니다.

**`engine/film.js`**

| 이름 | 설명 |
|---|---|
| `SHOTS` | 샷 배열. `main.js`에서 `push` |
| `film` | 상태 `{ f, idx, shot, playing, smooth, clock, cam, started }` |
| `seek(f)` | f 프레임으로 이동하고 그림 (소리 없음) |
| `play(on?)` | 재생/정지 토글. 끝에서 재생하면 처음부터 |
| `setSmooth(on)` | 스톱모션 ↔ 부드럽게 |
| `simTo(f)` | 그리지 않고 시뮬레이션만 f까지 |
| `render()` | 현재 상태를 그림 |
| `toWorld(sx, sy)` | 캔버스 좌표 → 월드 좌표 |
| `onChange(fn)` | 상태가 바뀔 때마다 `fn(film)` 호출 (UI 갱신용) |

**`lib/math.js`**

| 이름 | 설명 |
|---|---|
| `TAU`, `PI` | 2π, π |
| `clamp(x, a, b)` | 범위 제한 |
| `lerp(a, b, t)` | 선형 보간 |
| `inv(a, b, x)` | 역보간, 결과는 0~1 |
| `smooth(a, b, x)` | smoothstep |
| `eo(t)`, `eio(t)` | 이징 (cubic out / in-out) |
| `rng(seed)` | 시드 난수 생성기. `const R = rng(7); R()`는 0~1 |
| `hash(a, b, c)` | 정수 좌표 → 0~1. 상태 없는 난수 |
| `boil(id, e, amt)` | `[dx, dy, rot]` 노출 떨림 |

`rng`는 "순서대로 뽑는" 난수라 `build`나 `reset`에서 쓰고, `hash`는 "언제 물어도 같은 답"이라 `draw`에서 씁니다.

**`lib/noise.js`**: `noise(x, y)`는 −1~1 범위의 펄린 노이즈, `fbm(x, y, oct)`는 여러 겹을 합친 노이즈입니다.

**`lib/draw.js`**

| 이름 | 설명 |
|---|---|
| `mk(w, h)`, `g2(c)` | 오프스크린 캔버스와 그 2D 컨텍스트 |

| `blobPath(g, cx, cy, rx, ry, opt)` | 손으로 오린 타원 경로 `{ n, amp, seed, freq }` |
| `backdrop(w, h, opt)` | 인쇄된 배경판 `{ top, bottom, seed, mottle, dust }` |
| `stipple(g, x, y, w, h, opt)` | 점묘 먼지 `{ n, col, r, a, seed }` |
| `setCam(ctx, cam, p)` | 카메라 변환 적용 (p는 패럴랙스 깊이) |

**`engine/sound.js`**

| 이름 | 설명 |
|---|---|
| `emit(e)` | 물리 소리 (실제 재생 중에만) |
| `sfx(e)` | 즉시 소리 |

## 3.2 자주 하는 실수

| 증상 | 원인 | 해결 |
|---|---|---|
| 되감으면 장면이 조금씩 달라진다 | `Math.random`, `Date.now`, 또는 `reset`에서 초기화하지 않은 상태 | `rng`·`hash`를 쓰고, 상태는 모두 `reset`에서 새로 만든다 |
| 한 인형만 부드럽게 미끄러진다 | `draw`가 스냅 값이 아닌 실제 값(`b.x`)을 읽음 | `snap`에서 `rx`로 복사하고 `draw`는 `rx`만 읽기 |
| 키프레임 움직임이 끊기지 않는다 | `draw`에서 `st`나 실제 시간을 씀 | `draw`에서는 `sq` 사용 |
| 두 인형이 똑같이 떨린다 | `boil`의 `id`가 같음 | 인형마다 다른 `id` |
| 새 샷이 나오지 않는다 | `DUR`를 늘리지 않았거나 `SHOTS`에 추가하지 않음 | `config.js`와 `main.js` 확인 |
| 그림자·투명도가 다른 것에 번진다 | 캔버스 상태 누수 | `ctx.save()` / `ctx.restore()`로 감싸기 |
| 카메라를 움직이면 배경 가장자리가 빈다 | 배경판이 너무 작음 | 이동·줌 여유만큼 크게 굽고 음수 좌표에서 그리기 |
| 스크럽하면 소리가 쏟아진다 | 물리 소리에 `sfx`를 씀 | 물리 소리는 `emit` |
| 소리가 안 난다 | 오디오가 아직 열리지 않음 | 시작 오버레이나 캔버스를 한 번 클릭 |
| 페이지가 비어 있다 | `file://`로 열었음 | `python3 -m http.server` |
| 느리다 | `draw`에서 매번 복잡한 경로를 그림 | `build`에서 `sprite`/`backdrop`으로 굽고 `put`만 |

## 3.3 확장 사례: 필름을 게임으로 (`bounce-ball/`)

같은 폴더 옆의 `bounce-ball/`은 Seed Kit을 게임으로 바꾼 예입니다. 무엇을 바꿨는지 보면 프레임워크를 어디까지 늘릴 수 있는지 알 수 있습니다.

| Seed Kit | bounce-ball | 바꾼 이유 |
|---|---|---|
| 필름 하나 = 샷 여러 개가 이어짐 | 씬마다 따로 도는 시계 | 골을 넣어야 다음 씬으로 가야 하니까 |
| `DUR` 하나 | 씬마다 `dur` | 씬 3을 더 길게 |
| `poke`가 상태를 직접 바꿈 | 입력을 `{ f, dx }`로 **기록**하고 `simTo`가 그 프레임에 재생 | 관객의 입력도 결정론 안으로 |
| 샷 파일마다 코드 | `makeScene(cfg)` 팩토리 + 설정 파일 | 씬들이 같은 규칙(공·골대·장애물)을 공유 |
| 루프 | 시간이 끝나면 같은 씬을 처음부터, 골인하면 다음 씬 | 반복되는 애니메이션처럼 보이게 |

핵심은 **입력 기록**입니다. `simTo`의 반복문 안에 한 줄이 추가됩니다.

```js
for (const k of game.inputs) if (k.f === game.f) s.poke(k.dx);   // 기록된 입력을 제 프레임에 재생
```

이 한 줄 덕분에 관객이 개입해도 "같은 프레임은 같은 그림"이라는 약속이 지켜집니다. 되감기, 리플레이, 헤드리스 테스트도 그대로 동작합니다. 필름을 인터랙티브하게 만들고 싶을 때 가장 먼저 떠올릴 패턴입니다.

## 3.4 확장 아이디어

- **샷 전환 효과**: 앞 샷의 마지막 0.3초에 화면을 종이색으로 덮고, 다음 샷의 처음 0.3초에 걷어 냅니다. 각 샷의 `draw`가 자기 쪽 절반만 그리면 됩니다.
- **여러 인형**: 상태를 배열로 두고 `snap`에서 전부 복사합니다. `boil`의 `id`는 인형 번호로 줍니다.
- **재사용 소품**: `bounce-ball/game/props.js`처럼 `makeBall(r, color)` 같은 팩토리를 `lib/`에 모아 두면 샷이 짧아집니다.
- **음악**: 악보는 그냥 배열이니 반복문으로 박자를 찍으면 됩니다. `for (let i = 0; i < 16; i++) ev.push({ t: i * .25, k: 'tick', v: i % 4 ? .15 : .35 })`
- **영상 내보내기**: `?frame=0`부터 `NF-1`까지 헤드리스로 한 장씩 캡처한 뒤 `ffmpeg -framerate 60 -i f%04d.png out.mp4`로 묶습니다.
- **해상도 바꾸기**: `W`, `H`만 바꾸면 되지만, 샷의 좌표가 1920×1080 기준으로 적혀 있다면 함께 고쳐야 합니다.
